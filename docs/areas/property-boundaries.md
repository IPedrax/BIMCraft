# Property boundaries

`property_line {"points": [[0,0],[6000,0],[6000,4000],[0,4000]], "name": "Synthetic Plot"}` authors a named closed plot boundary, independent of terrain and geographic coordinates. Coordinates and segment lengths are millimetres, x east and y north. An optional `level` is an id, GUID or name; absent, the lowest level's plan is used. A repeated closing corner is removed. The existing bounded sketch solver rejects crossings, spikes, touching nonadjacent edges and zero-length edges; Model::check applies these rules to files and edits too. Generic modify/move/copy/rotate/mirror/delete and undo/redo use the ordinary command engine.

Plans show a pickable dash-dot boundary with name and area; ceiling plans and solid views omit it. Visibility/Graphics and Object Styles use category `propertyline`. The desktop's existing plan selection and Properties support Name, Level and Boundary. No dedicated terrain or survey UI is introduced. `elements {"category":"property lines"}` supplies area_m2, perimeter_m and segments with length (mm), survey-quadrant bearing and azimuth (degrees clockwise from north, rounded to one second). `schedule {"category":"property lines"}` lists Name, Level, Area and Perimeter in project units.

IFC4 exports one closed IfcPolyline per boundary in IfcSite's FootPrint / Curve2D representation. Site-local XY is independent of the native plan level; BIMCraft_PropertyLines stores Names, Guids and Levels in curve order so native identity and plan-level references return. Pset_SiteCommon.TotalArea is the sum of individual plot areas in square metres; overlapping plots are counted separately, not unioned. These curves have no volume. Import accepts only closed horizontal simple footprints, applies IFC units, placement and origin shift, reports unsupported curves and assigns a default name/lowest level when metadata is absent. Only the three recognized metadata arrays are borrowed; each must match the footprint curve count. Malformed metadata falls back without discarding valid geometry, and shared sets do not clone arbitrary property bags per site. Native element GUIDs are preserved through valid BIMCraft IFC metadata; generic IFC curves receive deterministic import identities.

Native format remains 18: prior readers strictly refuse the unknown propertyline enum category before a Model is produced. Existing fields and geometry defaults are unchanged; no old reader can reinterpret this element as different geometry. A future-version file is still refused. Independently landing format-changing PRs require ordinary rebase reconciliation.

Regression target: `cargo test -p bimcraft-core --test property_boundaries`; desktop: `cargo test -p bimcraft-ui-egui property_boundary`. Inspect a synthetic CLI plan PNG, schedule CSV, native save/reopen and IFC save/reopen; independently validate the IFC with IfcOpenShell EXPRESS checks, closed curves, bounds, areas, placement, units and unique GlobalIds. Full workspace/platform/IFC CI remains required.
